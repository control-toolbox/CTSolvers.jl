Strategies Catalogue ​

This page lists every strategy CTSolvers provides: what it wraps, which package activates it, and on which device it runs. Most users reach these strategies through OptimalControl.jl (e.g. solve(ocp, :adnlp, :ipopt)); the symbols used there are the strategy ids below.

NLP solvers — CTSolvers.Solvers ​

StrategyidLoadParametersBackend
Solvers.Ipopt:ipoptNLPModelsIpoptCPUInterior point (COIN-OR Ipopt)
Solvers.MadNLP:madnlpMadNLPCPU, GPUPure-Julia interior point
Solvers.MadNCL:madnclMadNCL, MadNLPCPU, GPUAugmented Lagrangian (NCL) on top of MadNLP
Solvers.Knitro:knitroNLPModelsKnitroCPUCommercial solver by Artelys (license required)
Solvers.Uno:unoUnoSolverCPUUnified Lagrange-Newton solver (interior point, SQP, …)

Every solver solves an NLPModels.AbstractNLPModel through CommonSolve.solve and returns a SolverCore.AbstractExecutionStats:

julia
using ADNLPModels, NLPModelsIpopt
using CommonSolve: solve

nlp = ADNLPModel(x -> sum(x .^ 2), ones(10))
stats = solve(nlp, CTSolvers.Solvers.Ipopt(max_iter = 100); display = false)

display = false silences the backend's output. Solvers.extract_solver_infos turns the stats into the (objective, iterations, constraints_violation, message, status, successful) tuple used to build an optimal control solution.

NLP modelers — CTSolvers.Modelers ​

A modeler chooses the NLP backend used to transcribe a discretized problem and carries its options. It does not build anything itself: the package providing the problem (e.g. CTDirect) builds the NLP model for each (problem, modeler) pair.

StrategyidLoadParametersBackend
Modelers.ADNLP:adnlpADNLPModelsCPUADNLPModels — automatic differentiation
Modelers.Exa:exaExaModelsCPU, GPUExaModels — SIMD abstraction, GPU-ready

ADNLP backends based on Enzyme or Zygote additionally require that package to be loaded.

Single precision

Modelers.Exa(base_type = Float32) builds a Float32 model, which only MadNLP accepts, with a tolerance reachable in single precision (e.g. tol = 1e-5). Ipopt, MadNCL and Uno have no method for a Float32 model. On the GPU, MadNLP runs on it but did not converge on the probe problem.

ODE integrators — CTSolvers.Integrators ​

StrategyidLoadParametersBackend
Integrators.SciML:scimlOrdinaryDiffEqTsit5 (or OrdinaryDiffEq, DifferentialEquations)CPU, GPUAny SciML ODE algorithm

Tsit5() is the default algorithm when OrdinaryDiffEqTsit5 is loaded; any other algorithm is passed through alg (e.g. alg = Vern9() after using OrdinaryDiffEqVerner). See Integration Results for what solve returns.

Several options have aliases (e.g. maxiter for Ipopt's max_iter, rtol for SciML's reltol); metadata lists them.

Choosing a parameter ​

CPU is the default for every strategy: Solvers.MadNLP() is Solvers.MadNLP{CPU}(). Pass the parameter explicitly to target the GPU — see GPU.
